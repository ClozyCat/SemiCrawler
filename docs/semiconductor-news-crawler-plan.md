# 半导体资讯采集与 AI 结构化工具实施方案

## 1. 目标与边界

建设一个无需用户登录、开箱即用的网页化工具。用户选择一个或多个半导体资讯来源，指定起始日期后启动任务；系统抓取符合日期条件的文章，调用 LLM 提取结构化信息，支持在线筛选、查看原文并下载结果表格。

第一阶段默认起始日期为 **2026-08-01**（包含当天），适配以下站点：

- 全球半导体观察（DRAMx）：`https://www.dramx.com/`
- 半导体产业网：`https://www.casmita.com/`

本期不包含用户身份识别、多人协作、云端账户、付费与定时自动执行。系统可先以本地单机服务运行，后续可平滑部署至内网服务器。

## 2. 现状与设计结论

现有 `index.html` 已包含来源选择、任务进度、结果筛选和 CSV 导出的交互原型，但数据、进度和导出均为前端模拟，尚不能进行真实抓取或 LLM 分析。

两个首期站点当前均可通过 HTTP 取得服务端渲染的文章页面，因此首期采集器使用 HTTP 请求与 HTML 解析即可，无须浏览器自动化：

| 来源 | 首期入口 | 采集策略 |
| --- | --- | --- |
| DRAMx | `/News/` 及其新闻分类页，例如 `/News/Memory/` | 遍历列表和分页，提取文章链接，进入文章页解析标题、发布日期和正文。 |
| 半导体产业网 | `https://www.casmita.com/news/list.php?catid=77`（项目动态） | 优先采集项目动态，后续按相同配置扩展企业动态、新闻资讯等栏目。 |

页面结构变化是长期风险。每个来源都必须有独立适配配置、试抓取、监控日志和失败告警，不能将所有来源的解析规则硬编码在一个爬虫中。

## 3. 总体架构

```text
浏览器工作台
    |
    v
FastAPI HTTP API
    |
    +-- 任务调度与进度日志
    +-- 来源配置管理
    +-- 采集适配器 -> 原始文章库 -> URL/内容去重
    +-- LLM 结构化 -> JSON Schema 校验 -> 结构化记录库
    +-- CSV / XLSX 导出
    |
    v
SQLite（首期本地持久化）
```

建议技术栈：

- 前端：React + Vite；保留并迁移现有原型的视觉与交互设计。
- 后端：Python 3.12 + FastAPI + Pydantic。
- 抓取：HTTPX、BeautifulSoup 或 lxml；Playwright 仅作为 JavaScript 渲染站点的后备能力。
- 任务：FastAPI 后台任务作为最小可用实现；后续可切换为 Redis + RQ/Celery，接口不变。
- 存储：SQLite + SQLAlchemy；本地无账户模式下无需外部数据库。
- LLM：后端通过 OpenAI 兼容 API 调用；密钥仅保存在服务端环境变量或本地设置文件，绝不发送至浏览器。
- 导出：Pandas + OpenPyXL 生成 CSV 与 XLSX。

## 4. 正式结果表结构

“资讯类型”是用户可见、可筛选、可导出的正式字段，不是仅供内部处理的字段。每篇原文可对应一条或多条记录，例如一篇文章同时披露两个独立项目时应拆分为两条记录，并保持相同原文链接。

| 字段 | 类型/格式 | 规则 |
| --- | --- | --- |
| 地域 | 文本 | 统一为中国大陆/中国台湾/海外，并尽量补充华东、华南等区域。 |
| 开发区/院校 | 文本 | 开发区、产业园、学校、实验室等；原文没有则为空。 |
| 企业名称 | 文本 | 项目主体、投资主体或核心企业；多个主体可用 `；` 分隔。 |
| 日期 | `YYYY-MM-DD` | 优先使用新闻发布日期；若表述的是项目事件日期，则在详细信息中说明。 |
| **资讯类型** | 枚举 | 项目立项、项目签约、建设开工、工程建设、设备进场、项目竣工、试生产/投产、产能扩建、融资/投资、并购重组、产品发布、研发进展、技术突破、产学研合作、政策/规划、招商引资、人才/实验室、供应链合作、经营动态、风险/事故、其他。 |
| 投资金额 | 文本 + 规范化数值 | 保留原文写法，并在内部保存币种、数值和单位；未披露填“未披露”。 |
| 产品/项目名称 | 文本 | 优先使用文章中明确的项目、产线、产品或技术名称。 |
| 信息来源 | 文本 | 站点名称，例如“全球半导体观察（DRAMx）”。 |
| 网址/原文 | URL | 文章规范化链接，可在页面中直接打开。 |
| 详细信息 | 文本 | 由 LLM 基于原文生成的事实摘要，必须涵盖事件、主体、地点、金额、阶段和时间等已知信息。 |

内部追溯字段包括：原文标题、原始正文、发布时间原文、采集时间、内容哈希、任务 ID、模型名称、LLM 输出、字段置信度、处理状态和错误信息。它们不强制出现在默认导出中，但可在后续增加“完整审计导出”。

## 5. 数据处理流程

1. 用户选择来源、输入起始日期（默认 `2026-08-01`）并创建采集任务。
2. 系统为任务建立来源配置快照，防止任务运行中配置变更影响结果。
3. 采集器请求栏目页与分页，提取并规范化文章 URL。
4. 对文章 URL 和正文内容进行去重；已完成的文章不重复调用 LLM。
5. 解析文章标题、发布时间、正文和原文 URL。发布日期早于起始日期时停止继续翻页或跳过该文章。
6. 清洗正文中的导航、广告、相关阅读和版权页脚，保留文章事实内容。
7. LLM 按预定义 JSON Schema 输出一篇文章对应的记录数组。
8. 后端校验枚举、日期、金额、URL 和必填字段；无证据字段置空或“未披露”，不得补造事实。
9. 保存结果、置信度和可追溯的原文证据，前端持续刷新任务进度。
10. 用户筛选、查看原文或修订单条记录后，下载 CSV/XLSX。

## 6. LLM 提取与质量控制

LLM 提示词应明确要求：

- 仅根据原文抽取，不推测未披露的金额、地点、企业或时间。
- 对每个独立项目输出一条记录；没有结构化价值的行业评论可输出空数组。
- `资讯类型` 必须从规定枚举中选择，不能自创分类。
- 金额保留原文表达，并单独返回可计算的金额数值、币种和单位；“约”“不超过”等限定词保存到备注。
- 每个非空字段返回对应的原文证据片段与置信度。

后端使用 Pydantic JSON Schema 强制校验模型输出。格式失败时自动进行一次带错误反馈的修复重试；仍失败则将文章标为“待人工处理”，保留原文与失败原因，不静默丢弃。

## 7. 来源扩展机制

第一阶段将来源脚本实现为可上传和可粘贴的 JSON“来源适配配置包”，而不是在服务器直接执行用户上传的 JavaScript。这样可满足后续扩展，并避免无账户网页环境中的任意代码执行风险。

示例：

```json
{
  "name": "半导体产业网 - 项目动态",
  "base_url": "https://www.casmita.com",
  "entry_urls": [
    "https://www.casmita.com/news/list.php?catid=77"
  ],
  "article_url_pattern": "/news/\\d{6}/\\d{2}/\\d+\\.html",
  "pagination": {
    "next_page_selector": "a.next"
  },
  "selectors": {
    "list_links": "article a",
    "title": "h1",
    "date": ".publish-date",
    "content": ".content"
  },
  "date_formats": ["%Y-%m-%d", "%Y年%m月%d日"],
  "request": {
    "rate_limit_per_minute": 20,
    "timeout_seconds": 20
  }
}
```

配置保存前必须执行：JSON Schema 校验、目标域名白名单校验、选择器试解析、最多抓取一篇样文预览。网页提供“测试配置”按钮，展示标题、日期、正文长度和首段，不直接启动全量任务。

第二阶段如遇复杂站点，再引入 Python 插件包。插件只能在隔离容器运行，并限制网络到声明域名、CPU、内存、文件系统和运行时长；不支持直接执行上传的 `.js` 文件。

## 8. 页面与 API 设计

### 页面调整

- 采集工作台：增加“起始日期”控件，默认值 `2026-08-01`；来源列表首期仅显示 DRAMx 和半导体产业网为已启用来源。工作台只负责创建任务、显示指标和最近任务，不再放置结构化结果表。
- 信息源管理：来源配置列表、新增/编辑 JSON 配置、上传 JSON、测试抓取和启用开关。
- 历史记录：独立 TAB 展示“结构化数据”“原始数据”“采集任务”。结构化数据支持全文检索及按地域、资讯类型、来源、日期筛选；原始数据支持标题、正文、网址全文检索，展示结构化状态，并可对待处理原文点击触发结构化。
- 采集任务：展示任务状态、时间范围、选中来源、抓取数、去重数、结构化数、失败数及运行日志。
- 结果详情：显示结构化字段、原文标题、原文正文、字段证据和置信度；允许本地直接编辑后再导出。
- 模型与导出：配置模型地址、模型名和 API Key；选择 CSV/XLSX 与默认/完整审计列集。

### 核心 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/sources` | 获取来源及启用状态。 |
| `POST` | `/api/sources` | 保存 JSON 来源配置。 |
| `POST` | `/api/sources/test` | 对配置进行单篇试抓取。 |
| `POST` | `/api/tasks` | 创建采集任务，传入来源 ID 和起始日期。 |
| `GET` | `/api/tasks/{id}` | 查询任务进度和统计。 |
| `GET` | `/api/tasks/{id}/logs` | 获取运行日志。 |
| `GET` | `/api/records` | 按筛选条件查询结构化记录。 |
| `GET` | `/api/analytics/overview` | 按相同筛选条件聚合高频词、实体共现关系和资讯类型分布。 |
| `PATCH` | `/api/records/{id}` | 修订本地记录。 |
| `GET` | `/api/articles` | 按标题、正文、网址查询原始文章及结构化状态。 |
| `GET` | `/api/articles/{id}` | 查看原始文章全文。 |
| `POST` | `/api/articles/{id}/structure` | 对尚未结构化的原文手动触发 LLM 结构化。 |
| `GET` | `/api/exports` | 下载 CSV 或 XLSX。 |

## 9. 分阶段实施计划

### 阶段 1：可运行基础与持久化

1. 创建前后端工程，迁移现有原型视觉风格。
2. 建立 SQLite 数据模型：来源、采集任务、任务日志、原始文章、结构化记录和导出记录。
3. 实现来源管理、默认日期、任务创建、状态轮询和真实 CSV/XLSX 下载。
4. 将“资讯类型”加入页面表格、筛选条件、数据库和默认导出列。

完成标准：应用启动后能够维护来源、创建任务和下载空/测试结果表，且默认起始日期为 `2026-08-01`。

### 阶段 2：两个首期采集器

1. 实现通用 HTTP 采集框架、节流、重试、超时、分页和 URL 规范化。
2. 编写 DRAMx 来源配置与必要的定制解析回退规则。
3. 编写半导体产业网“项目动态”来源配置与必要的定制解析回退规则。
4. 实现发布日期过滤、URL 哈希去重、正文哈希近似去重与原文存档。
5. 为两个站点准备固定样本 HTML 和解析测试。

完成标准：任一来源可按日期范围抓取文章；重复运行不重复保存；抓取失败能在任务日志中定位 URL 与原因。

### 阶段 3：LLM 结构化与审核

1. 增加模型设置和服务端密钥管理。
2. 定义结构化 JSON Schema、提示词、校验与修复重试机制。
3. 实现金额、日期和资讯类型规范化，保存字段证据和置信度。
4. 实现结果详情页和单条人工修订。

完成标准：抓取到的文章自动生成符合正式字段定义的记录；低置信度或异常输出进入待处理状态，不产生虚构值。

### 阶段 4：产品化验证与来源扩展

1. 实现 JSON 来源配置导入、编辑、试抓取和版本化。
2. 补齐任务记录、导出列集选择和审计导出。
3. 进行 UI、接口、解析、LLM Mock 和端到端下载测试。
4. 验证 robots.txt、站点使用条款、访问频率要求与版权边界；采集仅限公开页面，导出保留原文链接和来源归属。

完成标准：新来源可通过配置接入并完成试抓取；两个首期来源的核心流程稳定可用，页面、API 和导出通过回归测试。

## 11. 关联洞察实施方案（2026-08-20）

目标是在现有检索和结构化结果之上增加可追溯的高频词、实体关系和资讯类型分布，不改变采集主流程。

### 第一版：实时聚合

- 前端使用 Apache ECharts 展示关系网络、关键词排行和资讯类型分布；当前实现使用按需加载的 AntV G6 关系图组件，接口结构保持可替换。
- 后端增加 `GET /api/analytics/overview`，复用结构化数据现有的全文、地域、资讯类型、来源和日期筛选条件。
- 企业、机构、地域和项目作为四类实体；同一条结构化记录内的实体形成共现关系，节点大小表示出现次数，边宽表示共现次数。
- 高频词严格从“关键词配置”中取词，只展示在当前筛选结果标题、正文或结构化字段中出现过的配置词，并返回出现次数和涉及记录数；不再开放式展示“亿元”“科技”“基地”等通用词。未配置关键词时，第一版不展示高频词。
- 图中只返回权重最高的有限节点，每条边保留最多 10 个关联记录 ID，便于从图表回溯记录详情。
- 第一版实时计算且不新增数据库表，适合验证展示价值和实体质量。

### 第二版：实体规范化与显式关系

- 增加实体别名与规范名称，合并公司简称、全称及项目名称变体。
- 在 LLM 结构化输出中加入主体、关系、客体、证据和置信度，支持投资、合作、扩产、供应、建设、收购和产品发布等显式关系。
- 增加 `entities`、`record_entities`、`relations` 和 `article_keywords` 表，在结构化完成后持久化分析结果。
- 所有显式关系必须保存文章 ID、原文证据和置信度，图表不展示无法回溯的推断关系。

### 第三版：趋势与规模化

- 增加关键词增长率、关系时间线、来源主题差异和企业事件轨迹。
- 当实时聚合成为瓶颈时，使用后台任务增量更新分析表；数据规模进一步增长后再评估 PostgreSQL、Elasticsearch 或 Neo4j。

### 验收标准

1. 关联洞察页可使用与数据归档一致的主要筛选条件。
2. 空数据时展示明确空状态，有数据时关系图不超过配置的节点上限。
3. 节点类型、出现次数和关系权重可识别，点击节点可查看其直接关系。
4. 高频词同时返回总出现次数和涉及记录数，过滤常见无意义词。
5. 分析接口有自动化测试，前端生产构建通过。
